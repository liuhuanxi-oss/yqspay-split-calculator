# 分账比例、手续费和尾差怎么算？

有钱收分账计算器提供确定的单笔规则试算。以下约定是本工具的算法，不是支付通道的收费协议。

## 为什么比例合计相同，分到的钱却不同？

先确定基数。1,000 元订单扣除 3.80 元手续费，先扣后分的基数为 996.20 元；如果由某一方承担手续费，则先按 1,000 元计算各方分配额，再从指定方扣费。不能把两种方式混为同一结果。

比例和固定金额可混用，但比例乘以基数而非减掉固定金额后的余额。例如基数 1,000 元，固定货款 200 元、平台佣金 5%，佣金为 50 元，剩余 750 元。

## 一分钱分给三方怎么办？

订单 0.01 元，甲方比例 33.33%、乙方 33.33%、丙方接收剩余。两方比例精确总额为 0.6666 分，整体四舍五入为 1 分。两方小数余数相同，因此列表靠前的甲方得到 1 分，其他方为 0 分。

如果希望某一方始终获得尾款，应把规则约定写清楚。本工具的“剩余接收方”负责未分配余额，比例舍入补分仍按照最大余数规则执行，二者不是同一概念。

## 算法

金额转整数分；比例转万分比，所有乘法中间值使用 BigInt。

1. 计算订单手续费并检查其不超过订单金额。
2. 根据承担方式选择基数，检查固定金额加精确比例分配额不超过基数。
3. 比例分配额先向下取整分；计算比例精确总额四舍五入的目标值。
4. 将目标值与已分整分的差额按小数余数大小补给比例方；同余数按输入顺序。
5. 剩余方获得基数扣除固定金额与比例分配额后的余额。
6. 如指定承担方，则扣除其手续费；如分摊，按分配额加权，用同样的最大余数规则分摊总手续费。
7. 检查非负金额及“订单金额 = 手续费 + 各方净额”。

只有一个分配方时，设置为剩余接收方即可。手续费率为 100% 且无固定费用、选择先扣后分时，各方可全部为零。比例总计超过 100% 或精确分配超额时直接拒绝，即使超额还不到一分钱。

## 限制

只试算同一人民币订单，不包含退款、分账回退、阶梯费率、最低费、封顶费、税费和多级递归。不支持把分配方不足承担的手续费自动转嫁给其他人。不调用支付 API，不推断实际资格或到账时间。
